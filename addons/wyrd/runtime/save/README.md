# save

`WyrdSave.capture` / `apply` implement `WyrdRuntime.save_state` and `load_state`.

Schema version is 3. `WyrdSave.migrations` has two steps. The first fills `facts.believed` and `facts.held` when a schema 1 save is missing them. The second leaves the document unchanged. A schema 2 save has no `flight` key. It loads with empty token queues and a zero slice, and the dirty waits stay armed, the same result as a schema 2 load. A schema 3 save omits `flight` only when the rumor queue, the publish queue, the token queues, the slice, and the dirty waits are all empty. That load clears the dirty waits too. A version below 1, or a version this table cannot reach, is `E_SAVE_VERSION`. Schema 4 is refused with that same message. Load content first. Register rumor policies before loading a save that still has a mutation chain. The callables are not in the file. Load rebinds them from the policy id. A job or a reach row whose policy id is not registered adds `error[E_SAVE_POLICY]` and `push_error`. Both name the policy id and the deed. That deed's jobs, rumor tokens, reach rows, seen and queued sets, once-set, and copies are left out. Other rumors load. A belief already written stays. The load still applies.

The document holds pack id and manifest hash, language version, world, known, believed, and held facts, the deed log, relationship baselines and kinds, role bindings, definitions, frozen casts, and told sets, quest status, stage, outcomes, slots, host-step fields, frozen journal rows, and region leaves when a stage has them, effect provenance, play minutes, the game seed, and each named RNG stream's `to_state()`. `sequences`, when present, holds partial or finished sequence rows (`count`, `done`, and `started` or `matched` when set). A missing `sequences` key clears that bag only. An unknown sequence id is kept. Believed and held bags are sparse: an agent or group appears only when it has keys. `storylets`, when present, holds line-set draw rows and director `seen` / `last_minute`. `bark_speakers`, when present, holds bark speaker clocks (`cooldown` and `last_minute`). A missing `bark_speakers` key clears those clocks and leaves storylet rows. `why-not` reads those bags and does not add a key. The unlocked secrecy name is an ordinary world fact. Schema stays 2 and the save has no secrecy key. `WyrdConfig.secrecy_tiers`, `WyrdConfig.secrecy_fact`, and `WyrdConfig.trace_director` are host knobs and are not saved. An id the pack does not declare is kept and ignored. An unknown speaker id is kept.

`flight`, when any in-flight state exists, holds `rumor`, `publish`, and `scheduler`. Empty sections are omitted. The whole key is omitted when all three are empty. `rumor` holds `jobs` (chance, deed, key, kinds, max hops, policy id, claim value, verb), `seen` and `queued` (deed plus sorted who), `reach` (born, deed, key, level, pending, place, policy id, claim value, verb), `drawn` (`deed`, who), `held` (deed, value, who), and `gone` (deed, who). Mutation callables are not stored. `publish` holds `counters`, `covered`, and `queued` dues (`doc`, due). `scheduler` holds `rumor`, `publish`, and `cache_refresh` tokens in order, `waits` (sorted dirty condition indexes), and `slice` (leftover units, omitted at 0). A `StringName` claim is `{"t": "symbol", "v": "..."}`. A float claim is `{"t": "float", "v": n}`. Bool, int, string, and null stay JSON values. Load does not log `rumor_hop`, `rumor_adopt`, `rumor_reach`, `rumor_materialize`, or `rumor_mutate`.

A frozen issue, and a `skip <id>#<n> due=<minute>` line, stay in `facts` because those writes are ordinary world facts. The counter and the covered minute are restored with the queued dues, so a loaded issue is not numbered again and a skipped due is not published later. Load does not log `publish`. Cache entries, the deed index, and the storylet index are not save keys. `cache_refresh` tokens ride in `flight.scheduler`.

The rumor believer index is not its own save key. Each deed row in the `deeds` bag may carry `believers`, a list of `{t, who}` sorted by who. `t` is the adoption minute. Load rebuilds the index from those fields. `believed/` values do not name a deed or an adoption minute, so they are not enough to rebuild it. A save written before the field has the belief text and no deed link. Compaction rewrites the same bag: listeners from a merged group move onto the newest id, the earlier minute wins, and a dropped row takes its listeners with it.

The inspector snapshot is not a save key. Load does not log `debug_snapshot`. Deed compaction removes provenance rows whose facts are not marked `recap`. That still uses the `provenance` key. Load does not log `choice_summary`. Coverage counts are not a save key. Load does not log `coverage`. A console `set` stores provenance with scene `console` and choice `set` on the existing `provenance` key. Load does not log `console`. 64-bit values are lowercase hex so `JSON.stringify` does not round them. Other integers are coerced back to int on load. A scene must be closed. A hash mismatch adds `W_SAVE_MANIFEST` when `OS.is_debug_build()` is true and stays silent in a release. The load still applies.
