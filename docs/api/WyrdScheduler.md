# WyrdScheduler
Generated by tools/gen_api_docs.sh from the ## doc comments. Do not edit by hand.

**Experimental**

Inherits: `RefCounted`

Fixed-work queues for one game tick.

Queues, in round-robin order: waits, rumor, publish, cache_refresh, generate, ai_prefetch. A unit is one waiting-condition recheck, one rumor hop, one slice of a frozen issue, one cache-entry rebuild, one generate offer, or one AI pre-fetch visit. `run` spends at most the tick budget. Token queues keep a read cursor so a unit does not shift the array. The saved tokens are the ones still waiting. Generate and AI pre-fetch have no tokens. Their shares default to 0, so each runs only by spill when it has work and the earlier queues are idle. AI pre-fetch has work only when AI is active and a bark sweep has storylets left. Each queue's config weight is its share of that budget. Share a queue cannot use moves to the earliest queue that still has work, so a waits-only tick still spends the whole budget. A pass that would only run rumor is handled in one loop, including a spill onto rumor from an earlier idle queue. The loop stops when another queue would run, after finishing any later queue that the hop just gave work. Unfinished items stay in queue order. The round-robin starts at waits every tick. Token queues and the dirty waits are saved in `flight.scheduler`. The leftover slice is saved there too.
