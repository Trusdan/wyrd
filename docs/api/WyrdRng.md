# WyrdRng
Generated by tools/gen_api_docs.sh from the ## doc comments. Do not edit by hand.

**Experimental**

Inherits: `RefCounted`

In-script PCG32 (XSH-RR 64/32).

This is the minimal generator in pcg-c-basic `pcg_basic.c` (commit `bc39cd76ac3d541e618606bcc6e1e5ba5e5e6aa3`): multiplier `6364136223846793005`, `inc = (stream << 1) | 1`, then the XSH-RR output. The demo `pcg32-demo.c` in that commit, seeded `pcg32_srandom_r(&rng, 42u, 54u)`, prints round 1 of pcg-c `test-high/expected/check-pcg32.out` (commit `89b7dfbc5a50e5bf272cfac29dc435e81d2080d3`). Wyrd does not call Godot's built-in generator. A seed and stream produce the same sequence on every Godot version.  State and the increment are 64-bit. GDScript `>>` sign-extends, so every right shift of state is logical: `(v >> n) & ((1 << (64 - n)) - 1)` (`_lsr`). The step is one wrapping multiply-add, the same 64-bit wrap [WyrdHash] already uses. Seed and stream are the 64 bits of a GDScript [int].  [`stream_id`](#stream_id) is [`WyrdHash.of_string_name`](WyrdHash.md#of_string_name), so a named stream stays put across versions. [`for_decision`](#for_decision) builds its seed by folding, in order, `game_seed`, the stream name, `decision_key`, and `time_bucket` through [`WyrdHash.combine`](WyrdHash.md#combine), then uses [`stream_id`](#stream_id) as the PCG stream. Drawing from one decision does not advance another.  [`to_state`](#to_state) is version `1`. `state`, `inc`, and `seed` are 16-digit lowercase hex strings, because JSON numbers are floats and would drop bits above 2^53. `inc` is always odd. S2 saves each named stream's [`to_state`](#to_state). This class does not register streams.
