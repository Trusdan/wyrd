# WyrdPublish
Generated by tools/gen_api_docs.sh from the ## doc comments. Do not edit by hand.

**Experimental**

Inherits: `RefCounted`

Periodic issues for compiled documents.

[`enqueue_due`](#enqueue_due) pushes one `publish` token per missed issue, oldest first, up to [`WyrdConfig.publish_catchup_max`](WyrdConfig.md#publish_catchup_max). One token is one frozen issue, built a slice at a time. Each publish unit reads at most [`WyrdConfig.publish_slice_rows`](WyrdConfig.md#publish_slice_rows) candidate rows, then the same token stays at the front of the queue. The claim and the candidate rows are frozen on the first slice, so the finished line matches a one-shot build from that moment. Issues past the cap are numbered and written as `skip` lines in the document fact, so they are not published later. The in-memory counter, the covered minute, and the queued dues are saved in `flight.publish`. A half-built issue also stores `cursor`, the optional `beliefs` snapshot from the first slice, and the optional `claim` frozen with it. Load continues that issue from the snapshot. A save that has `cursor` and no `beliefs` starts the issue over and can log `phase=restart`. The gathered rows are dropped. Issue tokens ride with the scheduler. Schema stays 3. [`deeds_known_to`](#deeds_known_to) reads the verb index, the witness index, the hour buckets, and the believer field. Lookup off walks every row instead. A `saw` witness counts as `known`. `heard`, `inferred`, and a rumor believer count as `believed`.

### `import_state`

**Experimental**

```gdscript

```

Replaces counters, covered minutes, and the queued-due set. Issue tokens stay on the scheduler. A saved `cursor` with `beliefs` resumes that issue. Without `beliefs` the next slice starts over. The gathered rows are not restored.

### `deeds_known_to`

**Experimental**

```gdscript
func deeds_known_to(group: StringName, since: int, filter: StringName = &"") -> Array
```

Deed rows any current member witnessed, or believes through a rumor, at or after `since`. A witness uses the deed minute. A believer uses the adoption minute. `filter` empty keeps every verb. Otherwise it is the verb. Rows are unique by deed id and sorted by that id. `t` is the earliest qualifying minute. `mode` is `known` when any included member saw the deed, and `believed` otherwise. `knowers` lists those members once.

### `enqueue_due`

**Experimental**

```gdscript
func enqueue_due() -> void
```

Queues due issues that are not already frozen, skipped, or already queued. A visit takes at most the catch-up cap, oldest first. The rest are numbered and stored as skip lines in the document fact. The cap is per document.

### `issue`

**Experimental**

```gdscript
func issue(token: String) -> bool
```

Reads one slice of the frozen issue named by an `issue` token. Returns false when the token should stay queued. Other tokens are ignored and return true. The copy is written on the slice that finishes the cursor.
